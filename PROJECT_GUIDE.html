把一个交易想法，
变成可复核的研究。

Vibe-Trading 是一个开源金融研究工作台：你用自然语言提出问题，它连接行情、分析工具和回测引擎，产出报告与运行记录。它更像“研究助理 + 实验平台”，不是自动赚钱的策略。

一句话理解：模型负责理解问题、编排工具和解释结果；行情与计算引擎提供证据。结果是否可信，仍取决于数据、假设、交易成本和验证方式。

MAP / 01

它由哪些部分组成

仓库同时包含研究引擎、Agent 运行时和用户界面。你可以把它当作一个“带金融工具箱的 AI 应用”。

01
Research core

市场数据与量化计算

加载多个市场的行情与基本面数据，计算技术指标、因子、期权估值等，并由不同市场的回测引擎模拟策略规则。

02
Agent runtime

把问题拆成工具调用

Python Agent 使用 LLM 理解任务，调用行情、研究、回测、文档读取、报告等工具。记忆、会话和运行产物会保存在本地。

03
Ways in

CLI、Web、MCP 与 API

CLI 适合交互与脚本；FastAPI 提供本地服务；React 提供 Web UI；MCP 让其他兼容 Agent 调用金融工具。

FLOW / 02

典型研究任务怎么走

一个“测试 BTC 均线策略”的请求背后，大致经过这些阶段。每一步的产物都应该能被检查。

01 / ASK说清问题

标的、日期范围、策略规则和你想看的指标。

02 / FETCH取市场数据

从可用数据源取价格序列；来源与数据质量会影响结论。

03 / SIMULATE历史回测

按历史数据模拟策略何时持仓、何时空仓，并计算结果。

04 / AUDIT核对假设

检查样本、基准、成本、仓位、前视偏差和验证区间。

05 / REVIEW读报告做判断

运行卡记录配置和产物，帮助复查这次运行如何产生。

WORDS / 03

量化术语，先掌握这些

点击词条展开。把术语理解为描述“如何做实验、如何衡量结果”的语言即可。

量化策略 strategy

把交易决策写成规则：例如“短期均线上穿长期均线时持有，否则空仓”。规则越具体，越容易用代码重现和检验。

回测 backtest

拿过去的行情，按策略规则模拟“当时如果这么做会怎样”。它是历史模拟，不等于真实账户成交；若数据或规则利用了当时尚不知道的信息，结果会虚高。

因子 / Alpha factor / alpha

因子是把股票某种特征变成数字的办法，例如近期涨幅、估值或波动。Alpha 常指希望能预测相对表现的信号；名字里有 Alpha 不代表它真的能预测或盈利。

标的与 Universe asset / universe

标的是单个可交易对象，例如 AAPL 或 BTC-USDT。Universe 是研究允许选择的对象集合，例如沪深 300 成分股。先定集合可减少事后挑赢家。

收益率 return

资产价格相对起点变化的比例。价格从 100 到 105，简单收益率是 5%。不同频率（日、周、月）下的收益不可随意混在一起比较。

基准 benchmark

用来比较策略的参照方案，例如同期一直持有该资产（买入持有）。策略赚了钱，不代表它比简单基准做得好。

最大回撤 max drawdown

净值曲线从某个历史高点跌到之后低点的最大幅度。它描述“最难熬的一段跌了多少”，与最终收益不同，也不表示未来最大跌幅有上限。

Sharpe（夏普比率） risk-adjusted return

大致表示每承担一单位波动，获得多少超额收益。数字越高不一定越安全：对分布、样本长度、无风险利率和计算频率的假设都很敏感。

样本内 / 样本外 in-sample / out-of-sample

用来设计或调参数的数据叫样本内；事先留出、不用于调参的数据叫样本外。反复根据留出段改策略，它就不再是干净的样本外检验。

过拟合 overfitting

规则把过去的偶然噪声也学进去，因此历史表现漂亮、换一段时间就失效。参数越多、试过的方案越多，越需要独立验证与多重比较校正。

滑点与交易成本 slippage / costs

真实成交价可能比看到的报价差；手续费、税费、借券费也会减少收益。没有充分建模这些成本的回测，通常会比可执行结果乐观。

模拟盘与实盘 paper / live

模拟盘用虚拟资金或券商沙盒；实盘会发送真实委托、承担真实盈亏。项目的券商连接器能力各不相同，需要逐个确认权限、市场规则和风险限额。

READ / 04

哪些结论不能混为一谈

项目能帮你跑实验、组织证据；不能替代对实验设计的判断。

读数守则

历史赚钱 ≠ 未来赚钱。 回测结果受行情样本、数据源、复权方式、交易成本、成交假设和策略参数影响。

方向命中率高 ≠ 策略有效。 还要看盈亏幅度、仓位、回撤、交易次数、基准表现与统计不确定性。

工具有交易接口 ≠ 适合直接实盘。 市场规则、券商权限、下单限额、异常处理与人工监督仍需单独验证。

RUN / 05

在这个仓库启动

已按当前代码的配置安装后端和前端依赖。下面是本地开发模式的启动方式。

Backend · Python / uv

配置模型，再启动 API

# 在仓库根目录：安装 Python 依赖
uv sync --python 3.12
# 复制模板，并在 agent/.env 配置 LLM Provider 与模型
cp agent/.env.example agent/.env
uv run vibe-trading serve --port 8899
Frontend · React / Vite

另开终端启动 Web UI

cd frontend
npm ci
npm run dev -- --host 127.0.0.1
# 浏览器访问 http://localhost:5899
CLI only

只用终端

配置好 agent/.env 后运行 uv run vibe-trading 进入交互界面。一次性任务可使用 uv run vibe-trading run -p "..."。

Credentials

运行前的配置边界

LLM Key / 本地 Ollama 用于模型推理；市场数据 Key 通常按数据源可选；券商账号用于连接器。安装包不会自动创建这些授权。可以先用免费行情源体验研究流程。
